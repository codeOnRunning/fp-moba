# 从 M0 到可看的垂直切片：玩法纵深 + 美术场景规划 v0.2

> 适用项目：`fp-moba/`  
> 当前状态：M0 灰盒切片可玩（第一人称移动、Q、普攻、假人、HUD、死亡/复活）  
> 目标：让游戏从“能玩的技术 demo”变成“愿意连续玩 15 分钟、截图也拿得出手的垂直切片”。  
> 原则：**不推倒 M0 的移动/战斗骨架；先做统一美术，再补玩法密度，不先堆高模。**  
> 视觉方向板：[`art-direction-board.png`](./art-direction-board.png)
>
> **已选路线（2026-11-13）：**
> - 下一阶段：**先只做美术（Art Pass 1.0）**，玩法暂时保持 M0 的 Q + 普攻。
> - 美术方向：**暮色星穹 / 星辉峡谷**。
> - 资产路线：**CC0 场景模块 + 定制角色/敌人**。场景优先用 Quaternius / KayKit / Kenney 的 CC0 包；角色先做“CC0 骨架 + 定制外观”，风格锁定后再全定制。
> - 本文后面的 P1/P2 顺序按此调整为：**P0 方向锁定 → P2 场景 1.0 → P1 战斗 2.0 → P3 中路对决 → P4 打磨**。

## 1. 先诊断：为什么现在“玩法单一、场景丑”

### 1.1 玩法单一，不是因为没有 LoL 的全部系统

当前只有：

- 1 个主动技能（Q）+ 1 个普攻；
- 1 种敌人（训练傀儡）；
- 没有波次、没有关卡目标、没有 build 成长；
- 没有技能连招、没有敌方威胁分级、没有“躲/骗/反打”的博弈。

所以玩家在 2 分钟内就会问：

> “然后呢？我为什么要继续打这个木桩？”

**下一步不是立刻做 100 个英雄，而是先做“战斗循环的密度”**：

```text
观察敌人起手 → 走位/位移躲开 → 反手技能 → 打出硬直/印记 → 追击或撤退 → 下一波
```

### 1.2 场景丑，不只是模型面数低

“丑”通常由五个因素叠加造成：

1. **没有美术方向**：深蓝灰盒子 + 默认材质，缺少主色/辅色/点缀色；
2. **没有构图**：一条直路、两侧平墙、无地标，第一人称看不到“我走到哪了”；
3. **没有光照层次**：环境光太平均，缺少暖/冷对比和暗部；
4. **没有角色剪影**：胶囊 + 球体，远看无法辨认职业和威胁；
5. **没有动画/VFX/音频**：动作是滑行，命中是数字，世界没有“活着”的感觉。

**所以美术升级要同时做：美术方向 + 模块化场景 + 角色剪影 + 灯光 + 动画 + VFX + UI。**  
只换一个高模，其他不变，仍然会丑。

## 2. 推荐的美术方向：暮色星穹 / 星辉峡谷

### 2.1 一句话视觉

> **暮色星穹下的古代星象台：深靛夜空、断裂的金色拱门、青色星辉、品红敌辉、漂浮的星尘与远处巨大的星环。**

不是写实 3A，也不是纯卡通；是**可读性优先的风格化低多边形**。  
参考感觉：`Hades` 的清晰剪影 + `Wild Rift` 的色彩分区 + `Deadlock` 的立体地标，但体量小得多。

### 2.2 色彩脚本

| 用途 | 颜色 | 说明 |
|---|---|---|
| 背景/夜空 | `#0B1020` 深靛 | 不是纯黑，保留层次 |
| 地面/石材 | `#2A3448` 夜幕蓝灰 | 主体中性色 |
| 建筑/金色 | `#E8C77A` 月金 | 拱门、边缘、UI、神圣感 |
| 玩家星辉 | `#57E0F0` 星青 | 技能、法阵、友方提示 |
| 敌方星辉 | `#FF5C8A` 品红 | 敌人、危险、敌方弹道 |
| 辅助紫 | `#B794FF` 星紫 | 位移、空间、稀有物品 |
| 骨白 | `#D9D2C3` 骨白 | 雕像、布料、文字 |

**规则：**

- 玩家 = 青 + 金；
- 敌人 = 品红 + 暗红；
- 中立/环境 = 蓝灰 + 骨白；
- 所有技能必须能用颜色区分，不能全靠特效形状。

### 2.3 场景分区

一条 240m 的中路，分成三个视觉段：

| 区域 | 视觉主题 | 地标 |
|---|---|---|
| 蓝方基地 / 前段 | 星辉观测站，冷青 + 金色 | 断裂星环、蓝色旗帜、悬浮水晶 |
| 中路 / 中段 | 古代星象桥，蓝灰 + 骨白 + 金色 | 巨大拱门、破损星盘、中央符文圈 |
| 红方基地 / 后段 | 被星蚀侵染的祭坛，品红 + 暗红 | 红色裂纹、黑曜石尖塔、敌辉灯笼 |

**第一人称最关键的是“地标感”**：每 20-30m 要有一个能记住的物体，玩家才能感知移动速度和位置。不能只有平墙。

### 2.4 模块化场景套件（Blender / GLB）

先做一套可复用的“星辉遗迹”模块，不要每个场景单独建模：

- 地面：4m × 4m 石板、破损石板、符文地砖；
- 墙体：直墙、转角、断裂墙、矮墙；
- 拱门：完整拱、断裂拱、半拱；
- 柱子：圆柱、方柱、星盘柱；
- 装饰：旗帜、火盆、悬浮水晶、星环、锁链、碎石、雕像残件；
- 天空：渐变天幕 + 星环 + 远处山影 + 漂浮星尘。

**资产规格：**

- 低多边形，单件 300-1500 tris；
- 共用一张 1024/2048 贴图图集，或纯 vertex color；
- GLB + Draco 压缩；
- 同一套材质，减少 draw call；
- 静态场景合并/批处理，重复件 InstancedMesh。

### 2.5 角色与敌人模型

| 对象 | 剪影关键词 | 颜色 | 动画 |
|---|---|---|---|
| 星辉法师（玩家） | 尖帽/兜帽、长袍、月牙法杖、肩部星辉 | 深蓝袍 + 金边 + 青辉 | idle / walk / cast / hit / death |
| 石卫（近战） | 宽肩、石甲、发光核心、重拳 | 蓝灰石 + 品红核心 | idle / walk / slam / stagger |
| 星蚀术士（远程） | 瘦高、漂浮、破碎面具、法球 | 暗紫 + 品红 | idle / float / cast / teleport |
| 猎星者（突进） | 低姿态、双刃、残影 | 黑 + 青白刃光 | idle / dash / slash |
| 试炼守卫（小 Boss） | 巨型星盘核心、环形护盾 | 金 + 青 + 品红 | idle / shield / beam / death |

**先做 1 个玩家 + 2 个敌人 + 1 个小 Boss，不要做 10 个英雄。**  
每个角色必须有“远看能认出来”的剪影；颜色只做辅助。

### 2.6 光照与后处理

- 1 个暖色主光（月金）从侧上方打亮建筑边缘；
- 1 个冷色补光（星青）压暗部；
- 品红点光只放在敌方区域/敌人核心；
- 体积雾/高度雾，让远处有层次；
- 轻量 Bloom（只让自发光溢出，不要全屏泛光）；
- 暗角、轻微色差/颗粒可选，默认关闭；
- 角色脚下 blob shadow，小兵不投实时阴影；
- 目标：60 FPS，draw calls < 250，三角形 < 1.5M。

### 2.7 VFX / 音频 / UI

**VFX：**

- Q：青色星弧 + 拖尾 + 命中星屑；
- W：金色符文圈 + 延迟收缩 + 爆炸；
- E：紫色残影 + 空间裂缝；
- R：白金星束 + 镜头轻微拉伸 + 持续灼烧；
- 敌人技能：品红预警圈/线，先出预警再出伤害。

**音频：**

- 环境：低频风声、远处钟声、星尘噼啪；
- 玩家：脚步、法杖挥动、施法层（起手/飞行/命中）；
- 敌人：起手预警音、命中、死亡；
- 反馈：命中停顿、低血心跳、击杀音效。

**UI：**

- 技能图标从“符号”升级为手绘感图标；
- 冷却用扇形遮罩，而不是简单数字；
- 目标框、Boss 血条、伤害数字、击杀播报；
- 小地图先做“ lane 示意图”，不用完整战争迷雾；
- 保持现在的深色 + 金色 + 青色风格，但减少文字、增加图形。

## 3. 玩法纵深规划

### 3.1 方向选择：先做“战斗试炼”，再做“完整中路”

直接做完整 5v5 LoL 会把美术和玩法同时拖死。推荐两级：

#### v0.2：星辉试炼（战斗密度优先）

- 1 个竞技场（用星辉峡谷的一段）；
- 玩家 1 个英雄，Q/W/E/R + 被动；
- 3 种敌人（石卫、星蚀术士、猎星者）+ 1 个小 Boss；
- 5 波敌人，每波有组合变化；
- 每波结束 3 选 1 的临时强化（不是完整装备系统）；
- 5-10 分钟一局，死亡可重开；
- 目标：让“躲技能 → 反打 → 连招 → 处理多目标”成立。

#### v0.3：中路对决（LoL 骨架）

- 1v1 中路，玩家 vs 敌方 AI 英雄；
- 每 30 秒一波小兵（3 近战 + 1 远程）；
- 2 座塔 + 水晶；
- 金币/经验/等级/技能点；
- 6 件简化装备，基地商店；
- 敌方 AI 会补刀、换血、撤退、回城、推塔；
- 8-12 分钟一局；
- 目标：让“补刀 → 回城 → 出装 → 推塔 → 水晶”成立。

**v0.2 先解决“战斗不好玩”，v0.3 再解决“不像 LoL”。**

### 3.2 技能组 2.0（首版法师）

| 技能 | 设计 | 第一人称下的操作 |
|---|---|---|
| **被动：星辉印记** | 技能命中叠加印记，普攻/技能引爆，造成额外伤害 | 鼓励“技能 + 普攻”交替，而不是只按 Q |
| **Q：星弧飞弹** | 可蓄力 0.6s，蓄力越久伤害/速度越高；贯穿小兵，命中英雄停止 | 按住 Q 蓄力，松开释放；第一人称瞄准 |
| **W：引力法阵** | 在准星落点生成 4m 法阵，1s 后向内牵引并爆炸；可封走位 | 地面落点指示器；和 E/R 连招 |
| **E：折跃** | 向输入方向闪现 8m，留下 0.4s 残影；短暂无敌帧 | 躲技能、拉距离；不做穿墙 |
| **R：天穹裂隙** | 引导 2.5s 的旋转星束，可缓慢扫射；引导时移速降低 | 站桩高风险高回报；需要预判 |

**连招示例：**

- W 封路 → Q 蓄力逼走位 → E 调整角度 → R 扫射；
- 被动 3 层 → 普攻引爆 → 接 Q 收尾；
- 敌人起手 → E 穿过 → 反手 W + Q。

### 3.3 敌人设计：让玩家必须做选择

| 敌人 | 威胁 | 玩家应对 | 教学点 |
|---|---|---|---|
| **石卫** | 近战重击，起手慢、伤害高 | 侧移/E 躲，绕背输出 | 观察起手、不要站桩 |
| **星蚀术士** | 远程法球 + 短传送 | 贴近/打断/躲弹道 | 处理远程威胁 |
| **猎星者** | 突进 + 背刺，血少 | 预留 E、反手控制 | 保留位移、别乱交技能 |
| **试炼守卫** | 护盾阶段 + 环形激光 | 打核心/躲环形区域 | Boss 机制与阶段转换 |

**每个敌人至少有一个“起手预警 + 一个可躲的致命动作 + 一个输出窗口”。**  
没有预警的秒杀 = 挫败；没有输出窗口 = 木桩。

### 3.4 战斗反馈 2.0

- 命中停顿（hitstop）40-70ms，Q/R 重击更明显；
- 屏幕轻微震动，可调；
- 敌人受击闪白/闪红 + 硬直；
- 伤害数字分层：普通/技能/暴击/真伤；
- 低血心跳、屏幕边缘红晕；
- 击杀慢动作 0.2s（可选）；
- 技能命中音效分层：起手、飞行、命中、击杀。

### 3.5 关卡/波次设计（v0.2）

| 波次 | 组合 | 目的 |
|---|---|---|
| 1 | 2 石卫 | 教学：躲重击、绕背 |
| 2 | 1 石卫 + 1 术士 | 教学：同时处理近战/远程 |
| 3 | 2 猎星者 + 1 术士 | 教学：保留位移、优先杀脆皮 |
| 4 | 2 石卫 + 2 术士 | 压力测试：走位与目标选择 |
| 5 | 试炼守卫 + 2 猎星者 | Boss 阶段 + adds |

每波之间 3 选 1 强化：

- `星辉过载`：Q 蓄力速度 +30%；
- `引力井`：W 半径 +25%；
- `折跃余波`：E 落点造成小范围伤害；
- `星屑护体`：击杀敌人获得临时护盾；
- `棱镜折射`：R 引导时产生小范围折射弹。

**这是“build 成长”的最小版本，不需要完整装备系统。**

## 5. 资产与技术管线

### 5.1 模型来源（按优先级）

1. **混合方案（推荐）**：
   - 场景：CC0 低多边形模块包（Quaternius / KayKit / Kenney，需逐个核对许可证）+ 自定义改色/组合；
   - 角色/敌人：Blender 定制低模，保证剪影和配色统一；
   - 道具：程序化 + 简单 Blender 模型。
2. **全定制 Blender**：效果最好，但角色/动画工作量最大，适合 v0.3 后。
3. **纯程序化几何**：最快，但上限低，适合 M0，不适合作为最终视觉。

### 5.2 Blender → GLB 规范

- 单位：1 unit = 1m；
- 面数：场景件 300-1500 tris；角色 3k-8k tris；
- 材质：1 个材质/角色，使用顶点色或图集；
- 动画：idle / walk / cast / hit / death，30 FPS 采样；
- 导出：GLB + Draco；纹理 KTX2/Basis；
- 命名：`sm_` 静态、`sk_` 骨骼、`fx_` 特效；
- 碰撞：物理碰撞体单独用简单几何，不用渲染网格。

### 5.3 Three.js 渲染升级

- 角色：`MeshToonMaterial` 或带渐变 ramp 的自定义 shader；
- 场景：`MeshStandardMaterial` + vertex color + 轻量 emissive；
- 天空：渐变天幕 + 星环 + 远山剪影；
- 后处理：`EffectComposer` + 轻量 Bloom + 暗角 + 色调映射；
- 性能：静态场景合并、重复件 InstancedMesh、角色 LOD、blob shadow；
- 调试：保留 FPS/draw call 面板，增加“画质档位”。

### 5.4 性能预算（桌面 1080p）

| 项目 | 目标 |
|---|---|
| FPS | 60 |
| Draw calls | < 250 |
| 三角形 | < 1.5M |
| 同屏敌人 | ≤ 8（v0.2） |
| 动态光源 | 1 主光 + 2 点光 + 环境 |
| 纹理内存 | < 150MB |
| 初始加载 | < 15s |
| 包体 | < 25MB（压缩后） |

## 6. 建议的下一步（最重要）

### 推荐：先做 **v0.2 战斗试炼 + 美术 1.0**

理由：

- 它能最快解决“玩法单一”和“场景丑”两个问题；
- 不需要先做小兵/塔/商店，范围可控；
- 能验证“第一人称 MOBA 战斗”的核心乐趣；
- 美术套件做好后，v0.3 的中路可以直接复用。

### v0.2 的验收标准

- 3 个主动技能 + 被动，能打出至少 3 套连招；
- 3 种敌人 + 1 个小 Boss，各有明确起手/弱点；
- 5 波战斗，10 分钟内能完整结束；
- 场景有 3 个视觉分区、5 个以上可记忆地标；
- 玩家/敌人模型有明确剪影和 idle/walk/cast 动画；
- 至少 4 种技能 VFX、3 层命中反馈；
- 真实桌面 GPU 60 FPS；
- 截图/录屏能看出“这是一个有世界观的第一人称 MOBA”。
